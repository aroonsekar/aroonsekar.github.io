I worked through NextWork's URL shortener project and took notes in a file as I went. Rather than turn those into a tidy tutorial, I'm publishing them as they were written.

Python · Flask PostgreSQL Redis Docker Compose Base62

The code is on GitHub: aroonsekar/url-shortner. The guide I followed is NextWork's URL shortener project.

12:02 pm

Creating a URL-Shortner following instructions from Nextwork.

First starting with a brief intro about what a url shortner, why to use it and what is the system design behind it.

Then choices of stack, Python Flask Api , PostgreSQL, Redis cache, Docker, .

Seems like Python Flask API is used as both server as well as an API layer depending on how we use it. Like when I write it in the code, its basically an API layer(when we look at the code its like we mention how the data is handled etc.. ) and when we look at the architecture of the application/ program, it acts as a server listening to the network ports

Redis, basically as a cache to store hot data, for fast lookups and all and PostgreSQL, the database for persistent storage.

So the architecture was like User first create the short URL, which is stored in the PostGre db as original url with short url. when user tries to access the short URL, first the query is sent to redis cache and checked if the URL exists in the cache so we can serve it immediately, like quickly (fast lookup), if not the URL will be checked in Postgres and then given to the user(it'll be slow compared to the serve by redis), also once served, I think we'll store that in redis, in case if the user again access it we can give it to them quicky.
